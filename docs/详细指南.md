# 使用与维护

## 保存、导入和恢复

服务只在 127.0.0.1 监听，自动选择空闲端口。一个项目只启动一个服务；不同项目互不共享数据。启动窗口必须保持开启。页面没有自动保存，也不使用浏览器缓存存储项目。草稿可能因浏览器崩溃丢失，请及时保存。

「确认修改」仅修改当前草稿，「保存到项目」才写入 management/project.json。保存前服务检查结构、引用和路径；成功时保留旧数据到 management/recovery。历史备份会增长，可在项目归档时人工整理，工具不会自动删备份。

「导出 JSON」下载完整当前状态；有未保存内容时文件名为 project-draft.json。浏览器可能要求下载许可。导出不会自动替换 project.json，未保存标记不会因此消失。「导入 JSON」先读为草稿，需要确认，保存后才落盘。取消导入保留原草稿。导入旧修订不能直接覆盖新修订或改写已登记版本、封版和历史；需要先导出双方数据，重新载入最新状态，再有选择地合并可编辑字段。

发生 409 冲突时，不要反复点击保存：先导出自己的草稿、重新载入磁盘版本，再合并。不要让其他 AI 在服务运行时直接改 JSON。需要恢复旧数据时，先关闭服务和页面，备份当前 JSON，再选择 recovery 中的旧文件替换 project.json，运行 core.py 校验后重启。这是明确的人工回退，会连同当时的历史状态一起回退，应单独保留当前状态备份。

纯静态使用可以直接打开 management/index.html，再导入 JSON、编辑、导出，最后由用户替换项目 JSON。浏览器出于安全限制不能自动读取/写入本机项目文件、扫描体积或执行封版检查。完整功能请用本地服务。

## 材料归档

不另建 sources/records/scratch。00-brief 默认保留。30-work 留可编辑工程与完整依赖，不只留一张预览。40-review 放审核试渲染和对比；accepted 放通过后精选确认依据。50-versions 只在重要阶段留可回退快照，不复制每次修改。80-deliver 放确认交付，90-tmp 放按批次计算中间件。

稳定批次如 T012_窗户玻璃调整，可在同编号 40-review、90-tmp 下关联多个路径。一批材料只登记用途、来源/重建、保留成果、状态和阻碍，不逐文件维护台账。建批次、重要移交和收尾再更新。若审核包仍被版本审核引用，这批不能标为可清理；可把可独立处置的计算材料登记为另一稳定批次，避免误删证据。

可清理必须满足：用途明确、确认不是唯一副本、没有运行中写入、无阻碍、保留成果实际存在、没有其他记录/批次/封版引用、没有符号链接或重叠范围。服务会拒绝不满足条件的可清理状态。人工仍须检查保留成果可以打开、程序已停止写入；工具无法自动判断材料真实性和业务重要性。

清理预览列出每个确切范围、全部普通文件路径、数量、总字节、依据和保留成果。空目录不计入文件数。预览不执行删除；没有删除 API。任何自动或全局缓存清理均不在本包中。

1.1.0 起预览按体积从大到小排列，并给出 40-review / 90-tmp 分类汇总和总计。确认清单后可点「生成删除脚本」（或 `python3 management/cli.py preview-cleanup --write-script`），在 90-tmp 生成 cleanup-日期.sh 与 .bat：只含可人工复核项的确切文件，被阻止项不写入；工具不会执行它，运行时必须手动输入 DELETE。生成后如有变化，请重新预览、重新生成。

## 图片审核对比（1.1.0）

版本的工作路径里有 png/jpg/jpeg/webp/svg/gif 时，「版本审核」页会显示同任务上一张图片版本与本版：可并排看，也可切到叠图并用滑块调透明度（洋葱皮）。图片由本地服务只读提供，只能读取项目内的普通图片文件。静态模式不显示对比。

## 升级已建项目（1.1.0）

先关闭项目面板服务，在模板包里运行：

```sh
python3 tools/upgrade_project.py 项目目录 --dry-run      # 只看差异
python3 tools/upgrade_project.py 项目目录                # 只补缺少的文件
python3 tools/upgrade_project.py 项目目录 --apply-code   # 备份后替换管理代码，并迁移 project.json
```

旧代码与旧 project.json 备份在 management/recovery/upgrade-时间-from-旧版本/。AGENTS.md、PROJECT.md、目录 README 只报告差异，需要时人工合并；工作文件不会被读取、移动或删除。

## 审核、交付、结项与封版

版本登记不可编辑/移除，因此写错时用新编号登记正确版本，并在备注说明原记录作废原因。通过须填写结论和证据路径。一个版本一条当前审核，可编辑为退回；若它已有已验收交付，需先将交付改回待验收。同一任务的新版本不会继承审核。

费用可不填。结算记录的汇总必填，付款依据可填真实凭证的项目相对路径；记录金额或勾选验收都不表示完成付款。本工具不付款。

封版前先保存。服务检查范围/标准、完成任务、已验收交付、结项汇总、无运行中批次以及实际版本/交付/通过证据文件。封版保存完整登记快照，重复同一快照被阻止；历史不可用面板改写。之后可继续登记新阶段并再次封版。

封版锁的是登记信息，不会冻结业务文件本身或复制大工程。请把需要固定的版本指向独立文件或 50-versions 阶段包；修改实际同名文件不在本工具检测范围。人工确认和文件备份仍是交付完整性的依据。

## 已有项目接入

不直接对原项目套目录或搬文件。先读原规范，检查目录并准备映射：

```json
{"reviewedExistingRules":true,"directories":{"原工程":"30-work 的角色，保持原位置","参考":"00-brief 的角色，保持原位置"}}
```

保存为项目外的临时映射 JSON。执行：

```sh
python3 /模板包/tools/init_project.py /已有项目 --mapping /映射.json --dry-run
python3 /模板包/tools/init_project.py /已有项目 --mapping /映射.json
```

先看 dry-run 的 added 和 preserved。工具只增加缺少文件，不覆盖 AGENTS.md、PROJECT.md、旧管理代码或 project.json，不移动原材料，并把映射保存到 10-plan/existing-structure-map.json（已有同名文件则保留）。因此已有旧管理代码时，不代表自动兼容升级；必须检查 preserved 并人工接入。旧业务路径可直接用相对路径登记，未来新审核/临时材料才按新批次目录管理。

## 校验和故障

```sh
python3 management/core.py
python3 management/core.py --preview
```

服务异常结束可能留下 management/.server.lock，里面是启动 PID。先确认旧进程已退出，再手动移除此锁，不要在旧服务运行时删锁。端口被占用时使用默认自动端口或 `--port 新端口`。数据损坏时先保留现场再从 recovery 人工恢复。

本包不承诺断电时所有硬件上的持久性、网络盘并发或恶意外部编辑安全；推荐本机普通目录，不放共享同步盘让多设备同时写。脚本使用标准库，日常无需 Node；Node 仅用于开发测试。macOS 本机 Python 3.9.6 已验证，其他系统和浏览器需按自己的环境验收。
